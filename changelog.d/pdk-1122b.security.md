- fleetd now reports an agent whose running program file matches none of the published agent releases: it was
  replaced or modified on the device. This includes an agent started from another location or under another name.
  The new inventory policy `paddock_agent_binary_known` accepts the SHA-256 of
  every published agent artifact and is updated every inventory round, so a newly published release is accepted
  within one round. A failure records the new audit event `device.tamper_agent_binary_changed` (syslog MSGID
  `device.tamper_agent_bin_changed`) once per failure and opens a tamper finding on the device; only an evaluation of
  the current policy counts, so a regular update raises no event. A genuine older published release passes the
  policy (residual risk RR-149). The worker's new metric `paddock_inventory_policy_unanswered_hosts{policy}` counts
  hosts on which a Paddock policy query did not run. SIEM rules that match on the closed set of audit codes gain one code.
