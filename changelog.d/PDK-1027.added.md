- Organization administrators create a one-time sign-in setup link for a user on the user's page in the portal
  (*Create sign-in setup link*, with a step-up; `POST /api/v1/users/{id}/enrolment-link`). The link is valid for
  24 hours and shown only once; with it the account sets its password if it has none and a passkey. Each link is
  recorded in the audit log as `user.enrolment_link_created`, without the link itself. An account that is also a
  platform administrator gets no link from the portal; its link comes from the operator on the host.
- The operator creates the sign-in setup link of a platform administrator account on the control-plane host with
  `paddock-server admin enrolment-link --username <name>`; accounts that are not platform administrators are
  refused. Recorded as `platform.enrolment_link_created`.
- For 30 days after the upgrade the portal shows every administrator a notice about the passkey requirement with the
  number of administrators who still have to set one up (`mfa_enrolment_notice` in `GET /api/v1/me`). The notice can
  be dismissed.
