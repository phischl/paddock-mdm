- Upgrade: the default `PADDOCK_VALKEY_MEM_LIMIT` rises from 512m to 1g, so a control-plane host needs about 512 MiB
  more RAM. Valkey now sets its `maxmemory` to 60 % of its container limit with the policy `noeviction`: when full it
  refuses writes instead of being killed and never evicts a key. The upgrade recreates the Valkey container. Size the
  limit by `2 × (64 MiB + live devices × 2.0 KB + offboarded devices × 2.3 KB)` (`docs/operations/capacity.md`,
  "Memory limits"), which also gives the RustFS rule of 1 GiB per 20 000 objects, at least 2 GiB.
- `./paddock check --online` gains the item `valkey: memory headroom`: a warning when Valkey uses more than half of
  its memory limit, with the sizing rule.
- The worker's Valkey user may read device keys (`dk:`) and command lists (`cmd:`) with `HGETALL` only (a read-only
  ACL selector), so the cache sync can compare before it writes.
