- Commands that only check an account or open a session without a password, such as `sudo -u` or `sudo -n`
  without a password prompt, no longer print the directory login service's connection errors while the agent installs
  packages. The agent now has systemd remove the login service's socket files whenever the service stops. A password
  authentication during that pause (`sudo` with a password, `su`, a console login, the GDM password prompt) still
  waits about 1 second, shows two Himmelblau messages at the login prompt and prints one "timed out waiting for
  himmelblaud socket" line, also for local users; the local password check then decides as before.
- A `reset` removal now also takes the `himmelblau` entries out of `/etc/nsswitch.conf`, together with the login
  service's leftover socket files. A line in `/etc/nsswitch.conf` that was edited beyond the package's own addition is
  left as it is and logged in the removal's journal.
