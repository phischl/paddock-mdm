- Upgrade: the first start after the upgrade builds an index on `organization_id` for each of the 19 tables the
  organization deletion works through that had none (migrations 00139–00157); tables that already had such an index
  are left as they are. The indexes are built concurrently, so the database keeps serving writes, but on a large
  installation the start can take several minutes longer, mostly for `outbox` and `action` (devstack with 7.3 million
  `outbox` and 7 million `action` rows: TODO-LEAD). A concurrent build also waits for every transaction open in the
  database when it starts, so `up` takes longer while long transactions run. Do not interrupt the upgrade; if it is
  interrupted, running it again completes it.
- Deleting an organization on a large installation now finishes within its time bound: every check for the
  organization's remaining rows uses an index instead of reading whole tables, and the database step pauses after a
  few seconds and continues where it stopped, so a large organization no longer holds up the deletion of the others.
