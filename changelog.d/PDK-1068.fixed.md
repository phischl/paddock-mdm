- Upgrade: the first start after the upgrade builds an index on `organization_id` for every table the organization
  deletion works through (migrations 00139–00157). The indexes are built concurrently, so the database keeps serving
  writes, but on a large installation the start can take several minutes longer, mostly for `outbox` and `action`
  (devstack with 7.3 million `outbox` and 7 million `action` rows: TODO-LEAD). Do not interrupt the upgrade; if it is
  interrupted, running it again completes it.
- Deleting an organization on a large installation now finishes within its time bound: every check for the
  organization's remaining rows uses an index instead of reading whole tables, and the database step stops at the
  deletion round's time budget and continues where it stopped, so a large organization no longer holds up the
  deletion of the others.
