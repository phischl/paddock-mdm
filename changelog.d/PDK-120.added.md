- The audit index numbers every event per organization in the order the audit writer committed it (`commit_seq`), so
  consumers can read the audit trail without skipping late events from offline devices and can detect gaps. The
  upgrade numbers the existing events once; plan about 1.5 minutes per million audit events. On a large index, stop
  the audit writer before the upgrade so that new events wait in its queue (`docs/operations/capacity.md`). An event
  that a concurrent writer indexed first now fails the batch and leads to a redelivery instead of being skipped.
