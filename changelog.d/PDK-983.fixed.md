- On devices with directory logins, packages whose installation creates a local system account (for example Flatpak,
  which self-service needs for Flatpak applications, and many server packages) failed with "already exists, but is not
  a system user". The agent now pauses the login service while it installs or removes software and starts it again
  afterwards, at the latest after 10 minutes, with a systemd timer as a fallback if the agent stops. New directory
  logins and screen unlocks wait during an installation; running sessions continue. Every pause is recorded as
  `device.login_nss_shield`, and a stop of the login service by anyone else is reported as
  `device.tamper_service_stopped`. Installations that a local administrator starts with apt are not covered; the
  device login guide describes the workaround.
