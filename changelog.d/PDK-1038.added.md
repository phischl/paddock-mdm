- Once an organization's deletion has started, Paddock refuses every read and write of its data: the portal and API
  answer 403 `organization_inactive`, a device enrolling into it is refused with `identity_revoked`, and the worker
  drops its device messages, counted in `paddock_worker_dropped_total{reason="organization_unavailable"}`. The
  deletion finishes only after every request that was already running has ended, and only when no data is left.
- Every Paddock service keeps track of organizations that are being deleted. If it cannot refresh that list, it
  checks the organization on each request instead, logs a warning and counts the failure in
  `paddock_org_gate_refresh_failures_total`.
