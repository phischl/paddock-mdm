- Retention of control-plane history (ADR 0032 amendments 2026-10-18 and 2026-10-31, PDK-180): the worker's
  retention round now deletes finished device commands, cleared device alerts, filled event gaps and finished actions
  (the control-plane origin of audit events) once they lie before the start of the UTC month containing now −
  `PADDOCK_AUDIT_INDEX_RETENTION_DAYS` − 2 days, the oldest month the audit index may still show plus a margin for a
  late index purge and clock skew. It deletes per organization, and the platform pseudo-organization's actions once
  per round, in batches of 1 000 with one `retention.purged` event per store (`device_command`, `device_alert`,
  `device_event_gap`, `action`) that records the index retention as `index_days`. Open alerts, unfilled gaps,
  unfinished commands, started actions and commands a disk conversion or an uninstall still references stay. The
  database keeps a finished action unchanged for every role. `paddock_retention_stores` is now 8. Schema: migrations
  `00080`–`00082`.
- Upgrade: the control plane's `.env` (and a lab host's) must now set `PADDOCK_AUDIT_INDEX_RETENTION_DAYS`, to the
  audit host's value (`.env.example` sets 400). The worker reads it without a default of its own and does not start
  when it is missing, not a number, below 400 days or below `PADDOCK_AUDIT_RETENTION_DAYS`; `./paddock check` reports
  it, and every other `./paddock` command keeps working (`docs/operations/upgrade.md`). On a two-host installation
  keep both audit variables the same on the control-plane and the audit host.
