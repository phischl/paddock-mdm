- The retention round's Fleet breaker for the retired inventory (PDK-138) counts only failures of Fleet itself
  (`upstream_unavailable`: server errors, timeouts, connection errors). Fleet refusing to delete a single host now
  fails only that device with `invalid_state`, so a few permanently refused hosts no longer stop the retired-inventory
  purge of every organization. A retired device whose Fleet host is kept for a device of the same hardware no longer
  records a `device.inventory_purged` event with nothing deleted, nor counts in
  `paddock_retention_deleted_total{store="retired_inventory"}`, in every round; it records one event when its other
  rows are purged and the next one when the answer changes.
