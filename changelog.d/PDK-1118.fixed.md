- A slow disk on a device can no longer let an agent release that is not newer than the running agent past the
  downgrade check. If the running agent does not report its version within 10 seconds, the supervisor now defers the
  update instead of treating the agent as failed. It keeps the request, reports no result and retries after
  10 seconds, then with a doubling wait up to every 5 minutes. Each deferred attempt logs the warning `update request
  deferred: the active agent did not report its version in time` in the supervisor's journal and the diagnostics
  bundle. The portal shows such a device only as outdated, not why. If an agent binary that hangs keeps an update
  waiting, `docs/operations/agent-releases.md` (*An update that waits for the active agent*) describes how to recover
  on the device.
- A slow disk can no longer postpone the rollback of a failed agent release again and again. A supervisor restarted
  by its watchdog during a probation now keeps the original probation window. It waits at most another fifth of the
  window (2 minutes) so that a healthy agent can check in again. After a reboot of the device the window starts anew,
  as before.
