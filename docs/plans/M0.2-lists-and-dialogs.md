# Implementierungsplan: M0.2 — List contract and modal confirmations (ADR 0018)

Status: Ready for implementation · 2026-10-03 · Author: architect
Basis: ADR 0018 (Accepted), `docs/architecture.md` §17.1/§18, `CLAUDE.md` section "Portal and list endpoints"

Binding language: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal

Every list in the portal (device groups, audit log, organizations) offers search, filters, sortable columns,
pagination with page numbers and items per page (10/25/50/100), backed by one uniform admin-API list contract. Every
destructive action is confirmed in a modal; browser-native dialogs are impossible by lint rule.

## 2. Context

- M0/M0.1 shipped three collection endpoints with cursor pagination (`cursor`, `limit` 1–200, response
  `{items, next_cursor}`): `GET /api/v1/device-groups`, `GET /api/v1/audit-events`,
  `GET /api/platform/v1/organizations`. OpenAPI parameters `Cursor` and `Limit` in `api/openapi/admin.yaml`.
- SQL lives in `server/internal/adapters/postgres/queries/*.sql` and `server/internal/adapters/auditpg/queries/audit.sql`
  (sqlc). Portal views: `server/web/src/views/{DeviceGroups,Audit,Organizations}.vue` (Vuetify since M0.1).
- No `window.confirm/alert/prompt` exists today (checked); device-group deletion already uses a dialog, which becomes
  the shared `ConfirmDialog`.
- ADR 0018 (quoted essentials): parameters `page` (≥1, default 1), `page_size` ∈ {10,25,50,100} default 25, `sort`
  (allow list, `-` prefix descending, primary key appended as tie-breaker), `q` (2–100 chars, case-insensitive
  substring over documented fields), repeatable enum filters; response
  `{items, page, page_size, total, total_capped, sort}`; `page × page_size ≤ 10000` else 400 `page_out_of_range`;
  `total` counted with cap 10 000 (`total_capped=true` above); OpenAPI extension
  `x-paddock-list: {sort, default_sort, search, filters}`; contract test enforces it.

## 3. Binding decisions

1. **Breaking change** of the three list endpoints: `cursor`/`limit`/`next_cursor` are removed (no compatibility
   shim — pre-release). CHANGELOG entry under `Changed` with `**BREAKING:**`.
2. **SQL stays static sqlc SQL.** Dynamic sort is implemented with `ORDER BY CASE` branches per allowed sort value
   (one ascending and one descending branch per field), followed by `id` (or `event_id`) as tie-breaker. Search and
   filters use nullable parameters (`(sqlc.narg('q')::text IS NULL OR name ILIKE sqlc.narg('q_pattern'))`). No query
   builder library, no string concatenation of SQL.
3. **LIKE escaping:** `q` is escaped in Go (`\` → `\\`, `%` → `\%`, `_` → `\_`) and wrapped in `%…%`; queries use
   `ILIKE … ESCAPE '\'`.
4. **Count:** `SELECT count(*) FROM (SELECT 1 FROM … WHERE <same filters> LIMIT 10001) t`; `total_capped = count > 10000`,
   `total = min(count, 10000)`. Count and page query run in the same `InOrg`/`InPlatform` transaction (read
   consistency).
5. **Shared Go package** `server/internal/transport/http/admin/listing` (name free within the package path rule of
   §10) that parses and validates `page`, `page_size`, `sort` (against an allow list), `q`, and builds the response
   envelope. Handlers MUST use it; no handler parses these parameters itself.
6. **Endpoint specifics** (allow lists are binding):

   | Endpoint | `sort` allow list (default) | `q` searches | Filters |
   | --- | --- | --- | --- |
   | `GET /api/v1/device-groups` | `name`, `created_at`, `updated_at` (default `name`) | `name`, `description` | – |
   | `GET /api/v1/audit-events` | `occurred_at`, `code`, `outcome` (default `-occurred_at`) | `code`, `actor.display`, `target.display` | `from`, `to` (RFC 3339; default last 7 days; max range 92 days, 400 `range_too_large`), `code` (repeatable, exact), `outcome` (repeatable enum), `actor_type` (repeatable enum: admin, platform_admin, system, anonymous) |
   | `GET /api/platform/v1/organizations` | `slug`, `name`, `created_at`, `status` (default `slug`) | `slug`, `name` | `status` (repeatable enum) |

7. **Indexes:** new migration `server/migrations/paddock/00002_list_indexes.sql`: `device_group (organization_id, name)`
   exists (unique) — add `(organization_id, created_at)` and `(organization_id, updated_at)`; `organization (created_at)`.
   Audit DB migration `server/migrations/audit/00002_list_indexes.sql`: `CREATE EXTENSION IF NOT EXISTS pg_trgm` (run
   by `audit_owner`; if the role lacks the privilege, the migration runs it as part of the image init script instead —
   record which) and GIN trigram indexes on `code`, `(actor->>'display')`, `(target->>'display')`; B-tree
   `(organization_id, code)`, `(organization_id, outcome)`. Partition-aware: indexes are created on the partitioned
   parent.
8. **OpenAPI:** components `Page`, `PageSize`, `Sort`, `Search` parameters; response schemas
   `DeviceGroupPage`, `AuditEventPage`, `OrganizationPage` with the envelope fields; every collection `GET` carries
   `x-paddock-list`. `sort` is declared as `type: string` with an `enum` of the allowed values including the `-` forms.
9. **Portal components:**
   - `src/components/DataList.vue` — generic over the row type; props: `columns` (key, i18n title key, sortable),
     `fetch(params) → Promise<Page<T>>`, `filters` (declarative definitions: enum multi-select, date range),
     `searchable` (bool), `defaultSort`; emits `row-click`; slots for cells and row actions. Built on Vuetify
     `v-data-table-server`. Search debounced 300 ms; page resets to 1 on search/filter/sort/page-size change. State is
     synchronized with the route query (`page`, `page_size`, `sort`, `q`, filter keys); invalid query values fall back
     to defaults without error. Shows "10,000+" and a localized hint when `total_capped`.
   - `src/components/ConfirmDialog.vue` — props: `title`, `message`, `confirmLabel`, `destructive` (bool),
     `requireTypedText?: string` (confirm button disabled until the typed text equals it exactly); initial focus on
     *Cancel*; `Esc` cancels; returns a promise via a composable `useConfirm()`.
   - All three views use `DataList`; device-group delete uses `ConfirmDialog` (destructive, no typed text).
10. **Lint:** ESLint rules `no-alert: error` and `no-restricted-globals` / `no-restricted-properties` for `confirm`,
    `alert`, `prompt`, `window.confirm`, `window.alert`, `window.prompt`, and `no-restricted-syntax` for
    `addEventListener('beforeunload', …)`.
11. **i18n:** all new strings in `en.json` as ICU messages; the "x–y of total" pagination text uses ICU plural/number
    formatting; Vuetify's built-in data-table strings come through the existing `$vuetify` adapter.

## 4. Non-goals

New endpoints or screens, CSV export, saved filters, column chooser, infinite scroll, German catalog, changes to audit
event schema or WORM objects.

## 6. Interfaces

```go
// package listing
type Spec struct {
    Sort        []string // allowed fields without prefix, e.g. {"name","created_at","updated_at"}
    DefaultSort string   // e.g. "name" or "-occurred_at"
}
type Params struct {
    Page     int    // ≥ 1
    PageSize int    // 10|25|50|100
    Sort     string // validated value incl. optional "-" prefix
    Q        *string // nil when absent; already trimmed, 2–100 runes
    QPattern *string // escaped "%…%" pattern for ILIKE … ESCAPE '\'
}
func Parse(r *http.Request, spec Spec) (Params, error) // errors map to 400 invalid_request / page_out_of_range
func (p Params) Offset() int
type Page[T any] struct {
    Items       []T    `json:"items"`
    Page        int    `json:"page"`
    PageSize    int    `json:"page_size"`
    Total       int    `json:"total"`
    TotalCapped bool   `json:"total_capped"`
    Sort        string `json:"sort"`
}
func NewPage[T any](items []T, p Params, countUpTo10001 int) Page[T]
```

## 7. Implementation steps

1. **Contract and server** — OpenAPI changes, `listing` package (unit tests: every invalid value, escaping, depth
   limit, tie-breaker presence), migrations, sqlc queries, handlers. **Check:** `make gen lint test`; handler tests
   with OpenAPI validation for sort asc/desc per allowed field, search hit/miss incl. `%` and `_` literals, each filter,
   page beyond total (empty items, correct total), `page_out_of_range`, `total_capped` with 10 050 seeded rows
   (integration test on device groups). **Commit:** `feat(api)!: uniform list contract for collection endpoints`.
2. **Contract test** — `test/acceptance/list_contract_test.go`: for every collection `GET` in `admin.yaml`: has the four
   parameters and `x-paddock-list`; live call with each allowed sort (asc/desc) returns 200 and is ordered accordingly;
   unknown sort → 400; `page_size=7` → 400. Isolation test (A2) extended: search and filters as alice never return
   globex rows. **Check:** `make acceptance`. **Commit:** `test(acceptance): list contract gate`.
3. **Portal components** — `DataList`, `ConfirmDialog`, `useConfirm`, `listQuery` with Vitest tests (URL round trip,
   invalid query fallback, debounce, page reset, typed-text confirm, focus on Cancel, Esc). ESLint rules (decision 10)
   with a test fixture proving `window.confirm` fails lint. **Check:** `make lint-web`, Vitest.
   **Commit:** `feat(web): shared DataList and ConfirmDialog`.
4. **Views** — migrate the three views. **Check:** `make e2e` with new cases: per list search, sort toggle, filter,
   page size 10 → pagination shows page numbers, reload keeps state from URL; device-group delete via modal (cancel
   keeps the row, confirm deletes and audit shows one event); axe clean; no CSP violations.
   **Commit:** `feat(web): lists with search, filters, sorting and pagination`.
5. **Regression** — `make down V=1`, delete `.secrets/`, `make dev-secrets up dev-seed acceptance e2e`; all green.

## 8. Tests

As per steps. Existing tests that used `cursor`/`limit` are rewritten to the new contract with equivalent or stronger
assertions; none removed.

## 9. Acceptance criteria

| # | Given / When / Then | Req. | Observed by |
| --- | --- | --- | --- |
| AC1 | Given any list in the portal, then the user can search, filter (where filters exist), sort by each sortable column, choose 10/25/50/100 items per page and navigate by page number; reload keeps the state | ADR 0018 | Org admin, platform admin |
| AC2 | Given any collection endpoint, when called with an invalid `page_size`, unknown `sort` or a page beyond 10 000 rows, then it returns 400 with the documented code | ADR 0018 | Integrator |
| AC3 | Given a device group, when the admin clicks delete, then a modal asks for confirmation; *Cancel* changes nothing; *Delete* deletes it and exactly one audit event exists | ADR 0018, F7 | Org admin |
| AC4 | Given the web code base, when someone uses `window.confirm/alert/prompt`, then `make lint-web` fails | ADR 0018 | Developer |
| AC5 | Given org A, when searching or filtering any list, then no org B data appears | F10 | Org admin |

## 10. Freedoms

Package/file names inside the given directories, Vuetify component details, visual layout of filters, test helper
structure.

## 11. Stop conditions

`pg_trgm` cannot be installed in the audit DB by any role available in the dev stack; sqlc cannot express decision 2
for a required sort/filter; a requirement conflicts with ADR 0018 or `CLAUDE.md`; M0 §11 S2/S6/S7/S8.

## 12. Risks

| # | Item | Default |
| --- | --- | --- |
| R1 | `ORDER BY CASE` prevents index use for some sorts | Acceptable at current sizes; revisit with production data |
| R2 | Audit log counting on wide date ranges | Capped count (decision 4) and 92-day range limit |
