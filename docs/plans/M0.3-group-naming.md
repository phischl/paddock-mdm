# Implementierungsplan: M0.3 — Dot-separated Authentik group names

Status: Ready for implementation · 2026-10-04 · Author: architect
Basis: architecture v1.4 §9.2, ADR 0007 (amended 2026-10-04), ADR 0019, `docs/poc/M1-report.md` (finding "group claim")

Binding language: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal

All Authentik groups that Paddock creates or interprets use `.` as separator instead of `:`, so that the same group
names work for the portal and for Himmelblau device logins (Himmelblau silently drops claim values containing `:`).

## 2. Context

M0 introduced `paddock:<slug>`, `paddock:<slug>:admins|operators|auditors` and `paddock:platform:admins`. They appear
in the Authentik adapter, the BFF role resolution, the portal blueprint (application policy and groups mapping), the
dev blueprint, `devseed`, acceptance and unit tests, test data and docs. Organization slugs match
`^[a-z0-9][a-z0-9-]{1,30}[a-z0-9]$` and the slug `platform` is reserved, so dot-separated names are unambiguous.

## 3. Binding decisions

1. New names: `paddock.<slug>`, `paddock.<slug>.admins`, `paddock.<slug>.operators`, `paddock.<slug>.auditors`,
   `paddock.platform.admins`. (Later milestones add `paddock.<slug>.locked`, `.g.<group>`, `.d.<device_id>` — not now.)
2. Role resolution regex: `^paddock\.([a-z0-9][a-z0-9-]{1,30}[a-z0-9])\.(admins|operators|auditors)$`; platform:
   exact `paddock.platform.admins`. All other rules of M0 §6.7 unchanged.
3. Portal application policy: member of any group whose name starts with `paddock.`.
4. **Only Authentik group names change.** Other identifiers containing `paddock:` stay unchanged, in particular
   problem types `urn:paddock:problem:<code>` and any other URN or label.
5. No data migration: pre-release; development stacks are reset with `make down V=1`. `EnsureOrganization` creates
   the new names; old `paddock:` groups in an existing Authentik are neither deleted nor read.
6. Group names are defined in **one** Go place (`server/internal/domain/organization` or a new small package
   `server/internal/domain/identitynames`, choose one) as functions (`RootGroup(slug)`, `RoleGroup(slug, role)`,
   `PlatformAdminsGroup()`) and a parser used by role resolution; tests, devseed and the adapter use these functions.
   Blueprints (YAML) are the only other place where names are written literally.
7. CHANGELOG: `Changed` with `**BREAKING:**` "Authentik group names use `.` instead of `:` (`paddock.<slug>.admins`
   …). Development stacks: `make down V=1`. Existing installations: none (pre-release)."

## 4. Non-goals

Lock group, device groups, device provider, Himmelblau integration (M3); changes to `test/poc/**` (historical PoC
artefacts keep their names); any change to `docs/architecture.md`, `docs/adr/**`, `docs/plans/**`, `docs/poc/**`.

## 5. Affected files (found by `grep -rn "paddock:"`; verify each hit against decision 4)

`server/internal/adapters/authentik/{authentik.go,adapter_test.go,testdata/*}`,
`server/internal/transport/http/admin/{role.go,role_test.go}`, `server/internal/domain/organization/organization.go`,
`server/internal/testsupport/pgtest/pgtest.go` (only if it contains group names),
`deploy/compose/authentik/blueprints/paddock-portal.yaml`, `deploy/compose/authentik/dev/paddock-dev.yaml`,
`deploy/compose/compose.yaml` (only group-name hits), `test/acceptance/{login_test.go,audit_once_test.go,audit_chain_test.go,cmd/devseed/main.go}`,
`README.md`/`docs/operations/*.md` where they name groups, `CHANGELOG.md`. Hits in `api/openapi/admin.yaml`,
generated code, `server/internal/platform/httpx/httpx.go` and `server/web/**` are expected to be `urn:paddock:` or
similar and MUST stay unless they are group names.

## 6. Steps

1. **Do:** decisions 1–7. **Check:** `grep -rn "paddock:[a-z<]" --include=*.go --include=*.yaml --include=*.ts --include=*.vue --include=*.sh server deploy test/acceptance README.md docs/operations`
   returns only URN/problem-type hits; `make lint test`; `make down V=1 && make dev-secrets up dev-seed acceptance e2e`
   all green. **Commit:** `refactor(identity)!: dot-separated Authentik group names`.

2. **Timezone-independent retention test.** `TestConsumerDuplicateDelivery`
   (`server/internal/auditwriter/writer_test.go`) fails when the local date differs from the UTC date, because it
   compares the retention date (UTC recording day + 400 days) with a local-time expectation. **Do:** compute the
   expectation from the UTC recording day exactly as the production code defines it (architecture §14.4); scan the
   other `auditwriter` tests for the same pattern. **Check:** `TZ=Pacific/Kiritimati go test ./server/internal/auditwriter/...`
   and `TZ=Pacific/Pago_Pago …` both green, plus `make test`. **Commit:** `test(audit): timezone-independent retention assertions`.
3. **Robust dev-seed readiness.** `make dev-seed` still fails occasionally right after `make up` while the Authentik
   worker is applying blueprints, although the flow-readiness wait from M1 step 1 passed. **Do:** before the flow check,
   wait until every blueprint instance whose path is under the mounted Paddock blueprint directories reports status
   `successful` (`GET /api/v3/managed/blueprints/` with the bootstrap token), at most 300 s, interval 3 s; then the
   existing flow check. On timeout print the blueprint names and statuses. **Check:** five consecutive
   `make down V=1 && make up && make dev-seed` runs without retry. **Commit:** `fix(dev): wait for Authentik blueprints before seeding`
   + CHANGELOG `Fixed`.

## 8. Stop conditions

A `paddock:` hit whose meaning is unclear (group name vs. other identifier) and that is part of a public contract;
M0 §11 S2/S6/S7/S8.
