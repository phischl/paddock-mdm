# Implementierungsplan: M6b — Release readiness: load, German UI, supply chain, compliance pack

Status: Ready for implementation (after M6a) · 2026-10-07 · Author: architect
Basis: architecture v1.7 §2.3 (N1, N2, N6), §18 (i18n), §22 (test strategy, load), §25 (risks); concept C7, C8,
"Audit log" (ISO 27001 controls), "Licensing"; ADR 0018

Binding language: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal
Paddock is ready for a first public release: measured load figures, a complete German UI, license-checked and signed
release artifacts built by a release workflow, and a compliance pack operators can hand to their auditors.

## 2. Binding decisions
1. **Load test** (`test/load/`, k6 via image `grafana/k6` pinned — approved; tool only, not shipped): scenarios
   `checkin` (N1: 1 000 check-ins/s against one gateway replica, p99 < 200 ms, error rate < 0.1 %) and `ingest` (N2:
   5 000 events/s with 3 worker replicas, consumer lag stays < 60 s). Device identities are pre-generated by a Go helper
   (`test/load/cmd/identities`) through the real enrollment API. The k6 script signs requests with the device keys
   (WebCrypto ECDSA P-256 in k6 — if k6 cannot sign, use the Go helper as a load generator instead and record it).
   Results (hardware, numbers) go to `docs/operations/capacity.md`. A run that misses N1/N2 is a finding to report,
   not a stop: the coding agent profiles and fixes obvious hot spots (e.g. missing index, N+1 Valkey calls) within this
   plan and reports remaining gaps.
2. **German catalog** `server/web/src/locales/de.json` complete (every key of `en.json`, ICU plurals), audit-code
   display texts included; language switch in the user menu persisted per admin (existing `locale`); lint fails on any
   missing German key; e2e smoke in German (login, device list, audit page). Terminology: one glossary
   `docs/compliance/glossary-de.md` (e.g. "Sperre", "Gerätesperre", "Widerruf", "Treuhand-Ablage" for escrow).
3. **License gate:** `make lint-licenses`: `go-licenses` report for all modules (tool via `go run` at a pinned version —
   approved) and `license-checker-rseidelsohn` for npm production dependencies (dev dependency — approved), allow list
   `MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, MPL-2.0, BlueOak-1.0.0, 0BSD, CC0-1.0, Python-2.0,
   Unlicense`; anything else fails with the package name. Bundled container images are listed with their licenses in
   `docs/compliance/third-party.md` with their licenses (e.g. RustFS Apache-2.0, Fleet core MIT, Authentik core MIT,
   MySQL GPLv2 with FOSS exception), noting that bundled services run as separate processes and are not linked.
4. **Release workflow** `.github/workflows/release.yml` on tags `v*.*.*` (the architect writes this file; the coding
   agent MUST NOT edit `.github/` — it delivers the Makefile targets the workflow calls): `make release-artifacts`
   builds server images (`ghcr.io/phischl/paddock-server`, `-compiler`), the Debian packages and checksums; SBOM per image
   with `syft` (image pinned — approved); image signing with `cosign` keyless via GitHub OIDC (approved; no commercial
   service). Agent binaries stay signed offline with the release key (minisign) — the workflow attaches unsigned debs
   only as `-unsigned` drafts and the runbook `docs/operations/agent-releases.md` describes the offline signing step.
5. **Compliance pack** `docs/compliance/`:
   - `residual-risks.md`: every residual risk recorded in architecture/ADRs/plans so far, each with mitigation and what
     the operator records in the ISMS (root bypass, offline login window, no MFA offline, sudo lecture on sudo-rs →
     resolved by notice, Fleet free limits, enroll secret in bundles, Himmelblau synthetic NSS entries, dead man's switch
     and platform outages, escrow-reader trust in Authentik, TPM lockout on emulated vs. real hardware, …);
   - `iso27001-mapping.md`: A.5.33, A.8.15, A.8.16, A.8.17 (and A.8.1, A.8.2, A.8.5, A.8.9, A.8.24 where Paddock
     contributes) → Paddock feature, evidence (audit codes, WORM, hash chain, `audit verify`), operator duties;
   - `audit-codes.md` (generated, exists), `privacy.md` (exists, reviewed for completeness).
6. README for the public release: what Paddock is, screenshots (from e2e runs, light theme — Amendment 2026-10-08 (architect): the portal has no dark theme, so light only), quick start, links to
   install guide, compliance pack, CHANGELOG; CHANGELOG gets a `## [0.1.0] - <date>` section prepared but **not tagged**
   (tagging is the product owner's decision).

## 3. Steps
1. Load test + capacity doc (+ hot-spot fixes). 2. German catalog + glossary + e2e smoke. 3. License gate +
   third-party doc. 4. `make release-artifacts` (+ SBOM/cosign targets usable locally with `--dry-run`). 5. Compliance
   pack. 6. README + CHANGELOG section. 7. Regression (acceptance, e2e in en and de, `make lint` incl. licenses).
One commit per step.

## 4. Acceptance criteria
| # | Given / When / Then | Req. | Observed by |
| --- | --- | --- | --- |
| AC1 | Given the reference machine, then capacity.md states measured check-in and ingest figures against N1/N2 | C6, N1, N2 | Platform operator |
| AC2 | Given a German-speaking admin, then every portal text is German and audit events display in German while stored in English | C7, principle 6 | Org admin |
| AC3 | Given `make lint`, then no dependency with a non-allowed license exists | C8 | Platform operator |
| AC4 | Given the compliance pack, then an auditor finds controls, evidence and residual risks in one place | ISO 27001 | Auditor |

## 5. Stop conditions
A required tool is not available under an allowed license; a German string cannot be expressed without concatenation
(report the key); M0 §11 S2/S6/S7/S8.
