# Implementierungsplan: M0.1 — M0 follow-ups

Status: Ready for implementation · 2026-10-03 · Author: architect
Basis: `docs/architecture.md` v1.3, ADR 0010 and 0015 (both amended 2026-10-03), M0 report (commits `bca15fb`…`b33e316`)

Binding language as in `docs/plans/M0-foundations.md`: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal

Close the findings from the M0 review: operators get a `CHANGELOG.md`; every audit event is covered by a signed
manifest even when it arrives after its occurrence day was sealed; the portal no longer depends on an unmaintained
UI library and is fully typed (`<script setup lang="ts">`) under a strict CSP.

## 2. Context

- M0 is complete (all gates A1–A5, E1 green). The stack runs with `make up`.
- **Audit gap (M0 open issue):** `server/internal/auditwriter` dates objects and manifests by the events'
  `occurred_at`. An event recorded after its day was sealed is stored but covered by no manifest.
  Architecture §14.4 (v1.3) now says, quoted: *"The date in the object key, `audit_object.day` and the manifest day
  are the UTC date on which the audit-writer **recorded** the object (database transaction time), not the events'
  `occurred_at`. … Writer transactions have a 5-minute timeout, and day D is sealed at D+1 00:15 UTC … Object
  retention is `recording day + retention days`."*
- **Portal:** `server/web` uses PrimeVue 4.5.5 (last MIT release; PrimeVue 5 is commercially licensed). Product owner
  decision 2026-10-03: replace with **Vuetify**. Component scripts are currently plain JS because ESLint had no
  TypeScript parser; the Options API is enabled only because PrimeVue needed it.
- **CHANGELOG:** missing; required by `.claude/agents/coder.md` §6.

## 3. Binding decisions

1. `CHANGELOG.md` per Keep a Changelog 1.1.0 with `## [Unreleased]`; it MUST describe what M0 delivered, for operators.
2. Audit objects, `audit_object.day` and manifests are keyed by the **recording day** = `(transaction_timestamp() AT
   TIME ZONE 'UTC')::date` of the writer transaction that inserts the batch. `recorded_at` of every event in the batch
   = that transaction timestamp. The hour in the object key is the recording hour.
3. Every writer transaction sets `SET LOCAL transaction_timeout = '5min'` (PostgreSQL 17) as its first statement.
4. The sealer seals day *D* only when the current UTC time is ≥ *D*+1 00:15. The development-only
   `audit seal --day --org` command keeps working and is the only way to seal earlier.
5. Object retention: `RetainUntilDate = recording day + PADDOCK_AUDIT_RETENTION_DAYS` (00:00 UTC).
6. Index partitioning and API filtering stay on `occurred_at` (no change to `audit_event` schema or admin API).
7. Portal UI library: **Vuetify**, newest major whose license on npm is **MIT** at implementation time, plus
   `vite-plugin-vuetify`. `primevue` and `@primevue/*` are removed.
8. All `.vue` files use `<script setup lang="ts">`. Build define `__VUE_OPTIONS_API__: false`.
9. ESLint gets TypeScript support through `typescript-eslint` and `@vue/eslint-config-typescript` (approved new dev
   dependencies; newest majors compatible with the installed ESLint major).
10. **CSP nonce:** the `api` role serves `index.html` per request with a fresh nonce: 16 random bytes, base64 (std,
    no padding stripped). It replaces the literal placeholder `__CSP_NONCE__` in
    `<meta name="csp-nonce" content="__CSP_NONCE__">` and sets
    `Content-Security-Policy: default-src 'self'; style-src 'self' 'nonce-<nonce>'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`
    and `Cache-Control: no-store` on that response. Static assets keep their current headers and caching. The portal
    reads the meta tag and passes it as Vuetify `theme.cspNonce`. `'unsafe-inline'` MUST NOT appear in any CSP.
11. Vuetify's own UI strings come through Vuetify's vue-i18n adapter (`createVueI18nAdapter`), with Vuetify's `en`
    locale messages placed under the `$vuetify` key of the existing i18n instance. The existing `intl-messageformat`
    compiler stays for all Paddock messages.

## 4. Non-goals

- Production TLS/ACME overrides for Compose (scheduled for M6), CI execution, German catalog.
- Any visual redesign beyond what the library switch requires; no new screens, no new API endpoints.
- Changes to the audit event schema, the admin API contract or migrations.
- Any change to `docs/**` except `README.md`/`docs/operations/*.md` where they describe behaviour changed here,
  and `CHANGELOG.md`. `.claude/**` and `test/vms/**` MUST NOT be touched.

## 7. Implementation steps

1. **CHANGELOG**
   - **Do:** create `CHANGELOG.md`; under `[Unreleased]` → `Added`: operator-facing entries for M0 (Compose stack with
     control plane and separate audit domain; platform organization management with Authentik provisioning; portal
     login via Authentik with role mapping; device groups; audit log view; WORM audit store with signed daily
     manifests and `paddock-server audit verify`; organization isolation; dev seeding and acceptance tests);
     `Security`: RLS isolation, BFF session, strict CSP.
   - **Check:** file renders as valid Markdown; categories as in Keep a Changelog.
   - **Commit:** `docs: add changelog for M0`.

2. **Audit chain by recording day**
   - **Do:** decisions 2–5 in writer, sealer and verify; update `docs/operations/audit-bucket.md`; CHANGELOG `Fixed`:
     "Audit events recorded after their occurrence day was sealed are now covered by the manifest of their recording day."
   - **Check (new integration tests in `server/internal/auditwriter`):**
     - an event with `occurred_at` = two days ago, recorded today, lands in today's object key, today's
       `audit_object.day`, and today's manifest; `audit verify` over both days exits 0; the earlier, already sealed
       manifest is unchanged (same SHA-256);
     - a batch whose transaction exceeds the timeout (test sets a lower `transaction_timeout` through a test-only
       hook) is rolled back and redelivered, no object row is committed;
     - sealer refuses day *D* before *D*+1 00:15 UTC (injected clock);
     - retention date = recording day + retention days.
     Existing tests and `make acceptance T='TestAuditChain|TestWORM|TestAuditOnce'` stay green.
   - **Commit:** `fix(audit): chain audit objects by recording day`.

3. **TypeScript in Vue components**
   - **Do:** add the ESLint TypeScript dependencies (decision 9); convert every `.vue` file to
     `<script setup lang="ts">` using the Composition API; keep logic in `src/lib/*.ts` where it already is; no `any`
     without a justification comment.
   - **Check:** `make web lint` (ESLint incl. `@intlify/vue-i18n/no-raw-text`, `vue-tsc --noEmit`) and Vitest green;
     `make e2e` green with PrimeVue still in place.
   - **Commit:** `refactor(web): typed script setup components`.

4. **Vuetify and CSP nonce**
   - **Do:** decisions 7, 8, 10, 11. Replace all PrimeVue components with Vuetify equivalents (data table, dialogs,
     forms, app bar/navigation). Remove PrimeVue packages and the PrimeVue style-injection workaround in `main.ts`.
     Server-side nonce injection with a Go test. CHANGELOG `Changed`: "Portal UI library switched from PrimeVue to
     Vuetify (MIT); PrimeVue 5 requires a commercial license." and `Security`: "Portal CSP now uses a per-response
     style nonce."
   - **Check:**
     - Go test: two requests to `/` and to an SPA route (`/device-groups`) return different nonces; header nonce equals
       the meta nonce; no `__CSP_NONCE__` left in the body; `Cache-Control: no-store`; `/assets/*` unchanged;
       start-up fails with a template that has zero or two placeholders.
     - `make web lint`, Vitest, `make e2e` (E1 incl. axe: no serious/critical violations and **no CSP violation
       reports** in the browser console) green.
     - `grep -ri primevue server/web/src server/web/package.json` returns nothing.
   - **Commit:** `feat(web): switch portal to Vuetify with CSP nonce`.

5. **Full regression**
   - **Do:** `make down V=1`, delete `deploy/compose/.secrets/`, then `make dev-secrets up dev-seed acceptance e2e`.
   - **Check:** A1–A5 and E1 green.
   - **Commit:** only if files changed (`chore: …`).

## 10. Freedoms

Vuetify component choice and layout; file names below `server/web/src`; Go helper names; how the test-only
transaction-timeout hook is wired (MUST be inert unless `PADDOCK_ENV=development` or in `_test` code).

## 11. Stop conditions

- The newest Vuetify major is not MIT-licensed, or Vuetify cannot be made to work without `'unsafe-inline'`.
- Vuetify's messages break the `intl-messageformat` compiler and the adapter cannot isolate them.
- PostgreSQL `transaction_timeout` is unavailable in the pinned image.
- Any change would require altering the audit event schema, a migration, or the admin API.
- Any criterion in M0 §11 (S2, S6, S7, S8) applies.
