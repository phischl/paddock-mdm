# Implementierungsplan: M2.1 — M2 follow-ups

Status: Ready for implementation · 2026-10-04 · Author: architect
Basis: M2b report; architecture v1.5 §11.2 (amended: auto-stop for the current release)

Binding language: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal
Close the M2b review findings: auto-stop also protects a completed ("current") release, the agent's dependency tree
is vulnerability-checked and current, acceptance gates leave no data behind that disturbs real devices, the portal
e2e test does not depend on list position, and every commit builds the server image.

## 2. Context (from the M2b report)
- A completed rollout keeps offering its release, but the worker evaluates auto-stop only for `running` rollouts.
- `agent/go.mod` pulls `golang.org/x/crypto v0.13.0` through `aead.dev/minisign v0.3.0`; `govulncheck` was not run
  on the agent module.
- Acceptance gates leave organization-wide managed units (`a3-*.service`) in `acme`; real devices report them as
  unknown units.
- `server/web/e2e/portal.spec.ts` "organization admin manages a device group" fails once `acme` has more than 25
  device groups (new group lands on page 2).
- Commits 98c7f9a…783f94c broke `make up` because the Dockerfile did not copy `agent/go.mod` (fixed in df18824).

## 3. Binding decisions
1. **Auto-stop for the current release** (architecture §11.2 as amended): status `completed` keeps being evaluated
   every 60 s; failures (`agent.update_failed`, `agent.rolled_back` for this version) and offered devices are counted
   over the last 7 days; threshold rule unchanged (`>=`, same min/percent fields). Reaching it → `halted` (audit
   `agent_rollout.halted`, system actor), Valkey offer removed. Resume of a halted *completed* rollout restores the
   current-release offer.
2. **Dependencies:** `golang.org/x/crypto` in `agent/go.mod` is raised to the newest version compatible with `go 1.25.0`
   via an explicit `require` (no new dependency). `govulncheck` runs for **every** module (`pkg`, `server`, `agent`,
   `test/acceptance`, `test/system`) in `make lint`; any finding in reachable code fails lint.
3. **Test data hygiene:** every acceptance gate that creates organization-wide or group-scoped managed files/units,
   device groups or enrollment tokens deletes them in `t.Cleanup` (through the admin API, so the deletes are audited).
   Gates MUST NOT rely on cleanup of other gates. Units created by tests use the name prefix `paddock-test-` and are
   scoped to a device group that contains only simulated devices — unless the test is about org-wide scope, then it
   cleans up immediately after its assertions.
4. **E2E independence:** e2e tests locate their own rows by searching for a unique name (DataList search), never by
   position on the first page.
5. **Image build check:** `make lint` also runs `docker build --target build -f deploy/compose/Dockerfile .` (or the
   equivalent cheapest target that compiles all Go modules referenced by `go.work`), so a commit that breaks the image
   fails lint.

## 4. Non-goals
Any other change to rollout semantics, new features, M3 work.

## 5. Steps
1. Decision 1 with unit tests: completed rollout halts at the threshold within the 7-day window, does not halt with
   failures older than 7 days, resume restores the offer. Integration: devicesim reports `agent.update_failed` for a
   completed rollout → offer disappears. Commit `fix(releases): auto-stop for the current release` + CHANGELOG `Fixed`.
2. Decisions 2 and 5. Commit `build: govulncheck for all modules, image build in lint` + CHANGELOG `Security` entry for
   the x/crypto update.
3. Decisions 3 and 4; verify by running `make acceptance` twice in a row **without** reset, then `make e2e`, then
   `make system-test VM=paddock-u2604 T=S1` and check that the agent reports no unknown units. Commit
   `test: self-cleaning gates and position-independent e2e`.
4. Regression from reset: `make down V=1`, delete `.secrets`, `make dev-secrets up dev-seed acceptance e2e system-test VM=all`.

## 6. Acceptance criteria
| # | Given / When / Then | Observed by |
| --- | --- | --- |
| AC1 | Given a completed rollout, when failures reach the threshold within 7 days, then it halts and no device gets the offer | Platform admin |
| AC2 | Given `make lint`, then govulncheck has checked all modules and the server image compiles | Developer |
| AC3 | Given two acceptance runs without reset, then e2e and the system test S1 pass and devices report no unknown units | Developer |

## 7. Stop conditions
x/crypto cannot be raised without changing minisign's major version; govulncheck reports a vulnerability whose fix
needs a new dependency or Go ≥ 1.26; M0 §11 S2/S6/S7/S8.
