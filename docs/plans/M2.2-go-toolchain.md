# Implementierungsplan: M2.2 — Go toolchain upgrade

Status: Ready for implementation (after M2.1) · 2026-10-04 · Author: architect
Basis: ADR 0001 (Go), M2.1 QUESTION 2 (govulncheck findings GO-2026-6354/6355 fixed only in `golang.org/x/crypto`
≥ v0.56.0, which requires Go ≥ 1.26)

Binding language: **MUST** / **MUST NOT** / **SHOULD** / **MAY**.

## 1. Goal
All Go modules build and are tested with a Go release that receives security fixes, and `govulncheck` runs without
exclusions.

## 2. Context
M0 pinned `go 1.25.0` because the host had Go 1.25.6. Go supports the two most recent major releases with security
fixes; dependency fixes (x/crypto, sqlc, goose, oauth2, x/vuln) now require newer Go. `make lint` excludes
`server/internal/testsupport/...` from govulncheck since M2.1.

## 3. Binding decisions
1. **Target:** the newest stable Go major release available on the day of implementation (at least 1.26), latest
   patch. Set `go <major>.0` and `toolchain go<major>.<patch>` in every `go.mod`; `go.work` likewise; all build images
   (`golang:<version>-trixie`, pinned by digest in `deploy/compose/versions.env`) and CI use the same version. The
   host's older Go fetches the toolchain automatically (`GOTOOLCHAIN=auto`, default) — document this in
   `docs/operations/local-dev.md`.
2. **Dependencies:** raise the modules held back in M0/M2.1 because of Go 1.25 (`golang.org/x/crypto`, `goose`,
   `oauth2`, `sqlc`, `x/vuln`, and any other whose newest version needed Go ≥ 1.26) to their newest versions; no new
   modules. Regenerate sqlc/oapi-codegen output; a diff in generated code is expected only where the generator changed.
3. Remove the govulncheck exclusion and its Makefile comment; `govulncheck ./...` for every module MUST report 0
   findings.
4. Agent binaries stay static (`CGO_ENABLED=0`); check with `file`/`ldd` in a test.
5. CHANGELOG `Changed`: Go version; `Security`: x/crypto update.

## 4. Non-goals
Any functional change; new dependencies; refactorings beyond what the new versions require.

## 5. Steps
1. Decisions 1–4. **Check:** `make lint test`; `make down V=1 && make dev-secrets up dev-seed acceptance e2e`;
   `make deb && make system-test VM=all T='S1|S2|S4'` (both VMs back at `base-installed`, powered off).
   **Commit:** `build: upgrade Go toolchain to <version>`.

## 6. Acceptance criteria
| # | Given / When / Then | Observed by |
| --- | --- | --- |
| AC1 | Given `make lint`, then govulncheck covers all packages of all modules without exclusions and reports nothing | Developer |
| AC2 | Given the upgraded toolchain, then all gates (acceptance, e2e, system S1, S2, S4) pass | Developer |

## 7. Stop conditions
A dependency's newest version needs a newer Go than the newest stable release; generated code changes break the
OpenAPI contract tests; M0 §11 S2/S6/S7/S8.
